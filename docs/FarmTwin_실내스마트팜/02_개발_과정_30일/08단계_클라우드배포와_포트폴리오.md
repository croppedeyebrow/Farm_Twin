# 8단계 — 클라우드 배포와 포트폴리오 완성

## 기간

Day 28~30

## 목표

재현 가능한 공개 데모와 채용 평가자가 빠르게 이해할 수 있는 증거물을 만든다.

## 작업

### Day 28 — 배포

- [ ] Cloud VM 또는 컨테이너 호스트
- [ ] Docker Compose production profile
- [ ] HTTPS/WSS와 Nginx
- [ ] secret, backup, restart policy
- [ ] health/readiness 검증

### Day 29 — 문서

- [ ] README 5분 이해 구조
- [ ] 아키텍처와 데이터 흐름
- [ ] 폐쇄 루프 설명
- [ ] 데이터 계약과 ERD
- [ ] 부하테스트 before/after
- [ ] 로컬 실행·테스트 방법

### Day 30 — 데모와 릴리스

- [ ] 2~3분 데모 영상
- [ ] 정상 → 자동제어 → 회복
- [ ] 센서 고장 주입
- [ ] 부하테스트 결과
- [ ] release tag
- [ ] 공개 URL 최종 점검

## 데모 영상 순서

1. 프로젝트 문제와 가상화 범위
2. 가상 센서 스트리밍
3. 임계 초과와 자동 제어
4. 제어 되먹임과 상태 회복
5. 센서 고장과 품질 방어
6. 부하테스트 수치와 병목 개선

## README 첫 화면

- 한 줄 설명
- 30초 GIF 또는 영상
- 핵심 기술 5개
- 아키텍처
- 재현 가능한 Quick Start
- 성능 수치
- 실제 센서 교체 확장점

## 최종 검수

- [ ] 공개 URL 비로그인 확인
- [ ] 새 환경에서 Quick Start 확인
- [ ] migration과 seed 확인
- [ ] 핵심 테스트 CI 확인
- [ ] API key와 비밀번호 유출 확인
- [ ] 실제 제어 제품이 아닌 시뮬레이션임을 명시
- [ ] 미완성 기능은 로드맵으로 분리

## 완료 기준

- [ ] URL·코드·문서·영상 모두 접근 가능
- [ ] 폐쇄 루프가 3분 이내 재현됨
- [ ] 부하테스트 결과가 수치로 제시됨
- [ ] 기술 선택과 한계가 정직하게 설명됨
