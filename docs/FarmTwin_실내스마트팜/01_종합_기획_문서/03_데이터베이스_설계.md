# 데이터베이스 설계

## 1. DB 선택

PostgreSQL을 운영·시계열 저장소로 사용하고 PostGIS는 농장 좌표와 기상 기준점의 공간관계에 사용한다. MVP에서는 별도 시계열 DB를 추가하지 않는다.

## 2. 핵심 테이블

| 테이블 | 역할 |
|---|---|
| sites | 위치와 `geography(Point,4326)` |
| farms | 농장 정의 |
| rooms | 독립 제어 재배실 |
| racks | 재배 랙 |
| sensors | 센서 메타데이터·모델 버전 |
| actuators | 설비 메타데이터 |
| farm_states | 현재 환경 참값과 version |
| sensor_readings | 가상 센서 시계열 |
| control_rules | 규칙과 버전 |
| control_commands | 목표 명령 |
| control_events | 적용·정지·실패 결과 |
| simulation_runs | seed, clock, 모델 버전, 상태 |
| weather_snapshots | 외기 입력과 출처 |
| fault_injections | 고장 주입 정의·이력 |

## 3. 핵심 불변조건

- 한 simulation_run에는 active worker 하나
- sensor_reading은 simulation_run과 sensor에 귀속
- 원본 reading은 수정하지 않음
- 규칙 변경은 version 증가
- command와 event를 합치지 않음
- FarmState version은 단조 증가
- `sampled_at`, `ingested_at`, `simulation_time`을 구분

## 4. sensor_readings 주요 컬럼

```text
id, sensor_id, simulation_run_id, sequence,
value, unit, quality, source,
sensor_model_version,
simulation_time, sampled_at, ingested_at
```

권장 인덱스:

- `(sensor_id, simulation_time DESC)`
- `(simulation_run_id, sequence)` unique
- `(farm_id, simulation_time DESC)` 필요 시 비정규화 검토
- 오래된 시계열은 월 또는 일 단위 partition 검토

## 5. 공간 데이터

- sites.location: geography Point 4326
- weather_stations.location: geography Point 4326
- GiST index
- `ST_DWithin`과 거리 정렬로 가장 가까운 기준점 선택

## 6. 보존정책

| 데이터 | 정책 |
|---|---|
| 현재 상태 | 최신 1행/room + version |
| 원시 readings | MVP 전 기간 보관 |
| 집계 시계열 | 1분·5분 집계 확장 |
| control 명령·이벤트 | 영구 보관 |
| 부하테스트 원시 데이터 | run 종료 후 요약 보존, 원시는 선택 삭제 |

## 7. 트랜잭션 경계

한 simulation step에서 다음을 원자적으로 저장한다.

1. farm_state 갱신
2. sensor_readings 삽입
3. control_commands 삽입
4. control_events 삽입

실시간 발행은 commit 성공 이후 수행한다.

## 8. 마이그레이션과 seed

- Alembic revision 필수
- 초기 farm/room/rack/sensor/actuator seed 제공
- 테스트 DB는 migration으로 생성
- 운영 DB에 `create_all()` 사용 금지

## 9. 성능 검증

- batch insert 크기 비교
- 인덱스 전후 조회 계획
- run별 데이터 증가량 산정
- 부하테스트 중 connection pool 포화 확인
- 장시간 차트 조회에 시간 범위 제한
