# 데이터엔지니어링 설계

## 1. 목적

이 프로젝트의 데이터엔지니어링은 단순 DB 저장이 아니라 생성·검증·수집·정규화·보존·집계·재생 가능한 텔레메트리 흐름을 만드는 것이다.

## 2. 데이터 소스

- 외기 API: 실제 외기 온·습도
- replay dataset: 저장된 외기·센서 시계열
- environment simulator: 환경 참값
- virtual sensors: 오차·고장이 포함된 측정값
- load generator: 대량 합성 텔레메트리
- control engine: 명령과 적용 이벤트

## 3. 파이프라인

```text
Source
→ validate contract
→ normalize unit/time
→ quality classify
→ persist raw reading
→ update latest state
→ publish realtime event
→ aggregate/query/replay
```

## 4. 데이터 계약

필수 필드:

```text
event_id, event_type, schema_version,
farm_id, room_id, sensor_id,
simulation_run_id, sequence,
value, unit, quality, source,
simulation_time, sampled_at, ingested_at,
model_version
```

검증 항목:

- 필수 필드
- 단위와 범위
- 시간 역전
- sequence 중복·누락
- 알 수 없는 센서
- schema/model version

## 5. 품질 상태

| 상태 | 의미 |
|---|---|
| good | 정상 측정 |
| suspect | 범위·변화율·지연 이상 |
| bad | 고장 주입 또는 사용 불가 |
| missing | 기대 주기에 값 없음 |
| stale | 최신값이 허용 지연 초과 |

원시값은 보정값으로 덮어쓰지 않는다. 필요하면 `raw_value`, `normalized_value`, `quality_reason`을 함께 보관한다.

## 6. 시계열 처리

- 초기 MVP: PostgreSQL batch insert
- 관제: 최신값 WebSocket, 이력 REST
- 집계: 1분/5분 평균·최소·최대·품질 건수
- 장기 조회: 시간 범위와 최대 포인트 제한
- UI downsampling은 확장 단계에서 적용

## 7. 재현성과 lineage

각 결과는 다음을 연결해야 한다.

- simulation_run_id
- environment_model_version
- sensor_model_version
- rule_set_version
- schema_version
- random_seed
- 입력 외기 snapshot

이를 통해 동일 실험 재실행과 규칙 버전 비교가 가능해야 한다.

## 8. 부하데이터 생성

LOAD 모드는 정밀 상태전이 모델과 분리한다.

- 농장 수
- room 수
- 센서 수
- 센서별 주기
- 이벤트율
- 이상 비율
- 메시지 크기
- burst 패턴

부하 run마다 generator config와 결과 요약을 저장한다.

## 9. 부하테스트 지표

- events/sec
- DB rows/sec
- end-to-end p50/p95/p99
- WebSocket 전달 지연
- 오류·중복·누락률
- connection pool 포화
- CPU·메모리
