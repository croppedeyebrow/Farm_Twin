# 인프라·네트워크·클라우드 설계

## 1. 로컬 구조

```text
browser → nginx → frontend
                ├→ /api → FastAPI API
                └→ /ws  → FastAPI WebSocket

simulator worker → PostgreSQL ← API
monitoring ← API / simulator / DB
```

## 2. Docker Compose 서비스

- frontend
- api
- simulator
- db
- nginx
- prometheus(7단계)
- grafana(7단계)

## 3. 네트워크 경계

- public: nginx만 노출
- app network: frontend/API 연결
- data network: API/simulator/DB 연결
- PostgreSQL은 외부 공개 금지
- WebSocket은 `/ws` 경로로 reverse proxy

## 4. 클라우드 MVP

비용과 기간을 고려해 단일 VM 또는 단일 컨테이너 호스트에 Docker Compose로 배포한다.

```text
Internet
  → HTTPS/WSS
  → Nginx
  → frontend / api
  → simulator
  → PostgreSQL volume 또는 관리형 PostgreSQL
```

MSA·Kubernetes는 사용하지 않는다. 서비스 경계는 컨테이너로 보여주되 운영 복잡도는 억제한다.

## 5. 환경 분리

| 환경 | 목적 |
|---|---|
| local | 개발과 디버깅 |
| test | 자동 테스트 |
| load | 격리된 부하테스트 |
| production | 공개 데모 |

부하테스트를 공개 데모 인스턴스에 직접 실행하지 않는다.

## 6. CI/CD

### Pull Request

- Python lint/type/test
- TypeScript lint/type/test
- migration 검사
- Docker build

### Main

- 이미지 생성
- 취약점 검사 선택
- 배포
- health/readiness 확인
- 실패 시 이전 버전 유지 또는 복구

## 7. 보안

- API key와 DB password는 secret/env로 관리
- HTTPS/WSS
- 수동 제어 API에 데모 인증
- CORS 최소 허용
- rate limit
- DB 백업과 복구 절차
- 실제 설비용 안전제어가 아님을 명시

## 8. health 기준

- `/health/live`: 프로세스 생존
- `/health/ready`: DB와 필수 의존성 준비
- simulator heartbeat
- WebSocket 연결 수
- DB connection pool 사용량

## 9. 복구 시나리오

- API 재시작: DB snapshot으로 복구
- simulator 재시작: 마지막 committed state와 clock 복구
- 외기 API 장애: 마지막 정상값 또는 replay
- WebSocket 단절: REST snapshot 후 재연결
- DB 장애: 쓰기 중단, 불완전 제어상태를 정상으로 표시하지 않음
