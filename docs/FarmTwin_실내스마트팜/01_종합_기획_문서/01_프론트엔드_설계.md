# 프론트엔드 설계

## 1. 책임

프론트엔드는 운영 상태를 해석하고 조작하는 관제 클라이언트다. 환경값을 직접 생성하거나 제어 규칙을 판정하지 않는다.

## 2. 기술 구성

- React + TypeScript + Vite
- React Three Fiber 또는 기존 Three.js 모듈
- ECharts
- TanStack Query: REST 서버 상태
- Zustand: 화면·선택·시뮬레이션 UI 상태
- Zod: WebSocket 메시지 런타임 검증
- Vitest + Playwright

## 3. 화면

### 통합 관제

- 3D 재배실, 랙, 센서, 가상 설비
- 실내 온도·습도·CO₂·배지수분·PPFD KPI
- 외기 온·습도와 데이터 모드
- 자동/수동 모드와 액추에이터 상태
- 실시간 시계열과 제어 이벤트 타임라인

### 시뮬레이션 실험

- 초기 상태, seed, 시간배속
- API/REPLAY/SYNTHETIC 선택
- 실행·일시정지·재개·종료
- spike/stuck/dropout 고장 주입

### 부하테스트 결과

- 센서 수, 농장 수, 이벤트율
- p50/p95/p99 지연
- 처리량, 오류율, 누락률
- CPU·메모리·DB 연결 상태

## 4. 데이터 흐름

- 초기 구성·이력·복구: REST
- 최신 측정·상태·제어 이벤트: WebSocket
- 재연결 직후 REST snapshot 조회 후 스트림 재개
- `sequence` 누락 시 이력 보충 요청

## 5. 3D 표현 규칙

| 상태 | 표현 |
|---|---|
| 정상 | 녹색 |
| 주의 | 주황색 |
| 위험 | 적색 점멸 |
| 센서 불량 | 회색과 끊김 표시 |
| 관수 | 물 흐름 |
| 팬 | 회전 |
| LED | 랙 조명 밝기 |
| 냉난방·제습 | 상태 배지와 공기 흐름 |

3D는 CAD가 아니라 상태 탐색 인터페이스다. 정밀 모델링보다 선택, 강조, 원인 추적을 우선한다.

## 6. 상태 분리

- 서버 상태: farm, room, sensors, readings, rules, events
- 실시간 상태: latest readings, connection, sequence
- UI 상태: selected rack/sensor, chart range, modal
- 명령 상태: pending/succeeded/failed

## 7. 성능 기준

- 관제 기본: 센서 5~50개, 1~2초 갱신
- 차트는 고정 길이 ring buffer 사용
- 3D 객체는 재사용하고 불필요한 React 렌더링 억제
- 탭 비활성화 시 차트 렌더 주기 축소
- 부하모드에서 모든 가상 센서를 3D 객체로 만들지 않는다.

## 8. 오류 UX

- WebSocket 연결 상태 표시
- 마지막 수신 시각 표시
- stale/bad 품질을 정상값과 명확히 구분
- 제어 명령 실패 시 기존 상태를 낙관적으로 확정하지 않음
- API 장애 시 replay/synthetic 전환 여부 안내

## 9. 테스트

- 메시지 스키마 검증
- sequence 누락과 재연결
- 센서 상태별 색상
- 자동/수동 명령 충돌 표시
- 3D 센서 선택과 차트 연동
- 핵심 데모 Playwright E2E
